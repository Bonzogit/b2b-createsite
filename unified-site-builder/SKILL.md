# 统一网站建站

统一后台、业务接口与数据行为，按品牌和买家任务设计前台。用户只提供产品或服务名称即可开始；缺少企业事实时留作待配置，不编造资质、产能、案例或联系方式。可运行基础后台仍需补齐客户内容、设计、素材和外部集成。

路径相对本文件。首次接收完整包或更换 Agent 时读 [跨平台交接](references/portable-handoff.md)，定位真实参考库和已有工程。只要求学习、分析或检查 Skill 时完成该任务，不创建网站。

## 保持的业务行为

- 中文真实后台，默认维护英文源内容；用户可指定其他语言。联系方式集中配置，公开入口读取同一数据。
- 询盘与私密附件先持久化再返回成功；邮件状态独立，发信失败不丢询盘。打开 WhatsApp 不算已发送。
- 文章发布、修改及下架同步列表、详情和元信息，失败保留旧版，无需重新上传 ZIP。
- 初始英文、完整中文及 en/zh/es/ar/ru/fr/de/pt 8种语言选项；其余6种缺失译文按需生成；后台可一键翻译所选或全部目标语言，独立选择前台展示语言，文章保存/更新/发布默认自动排队翻译所选目标语言，可关闭或调整。人工译文 → 有效初始中文 → 持久缓存 → 引擎，改文只失效受影响块。
- 新工程默认 Hy-MT2，凭据在服务端注入；其他引擎按明确选择启用，失败不跨供应商切换。含中文括号、品牌或型号的正文按 [混排识别](references/translation.md#中英文混排与页面识别)处理。
- 发布后的线上内容是来源，初始示例只首次导入；升级不覆盖用户编辑、账号、询盘和附件。主要正文直接包含在 HTML 响应中。

## 完整建站流程

### 1. 内容和工程

按基础框架确定买家、页面职责、内容深度、询盘路径和后台管理项，记录 docs/SITE-BRIEF.md。已有工程先检查并复用；新工程用 scripts/create_site.py 创建空目录基础后台，再扩展客户内容及前台。用 [协议模板](assets/site.contract.json)记录实际实现，声明不代替接线。

完整网站默认交付服务器和 Cloudflare 两个独立 ZIP，共用业务代码、前台、后台及翻译核心，分别适配入口和存储；用户只要一个平台时照其要求。实际部署默认沿用用户 Ubuntu 工作台，Cloudflare 包不代表自动发布第二个网站。整理与打包细节集中在 runtime-profiles.md。

### 2. 参考和素材

按设计及参考选择规范定位真实共享库，实际查看采用的演示页面，允许整站参考或模块组合。记录 docs/design-record.json；docs/DESIGN.md 记录字体、色彩、间距、图片用途及实际素材。找不到库或看不到画面时如实记录，空白模板和文字目录不算视觉观察。

真实产品和企业素材优先；缺少适合的场景或概念图时使用宿主图像工具实际制作、保存并接入页面。图片数量由内容决定；生成图不能充当真实工厂、认证或客户案例证据。只有提示词或占位图不能算图片完成。

### 3. 样板和功能

用实际内容与素材完成首页、代表详情及询盘，实际查看电脑和手机后扩展全站。复用标准业务接口，不随前台参考另造后台规则。邮件按 Resend 规范接入；翻译按 v2 安装公共模块、词汇库、持久仓库和前台，安装完成不等于服务接通。

### 4. 验证与交付

按验收规范用隔离数据检查业务、权限、发布、重启及升级保留，查看电脑、平板、手机及适用的 RTL 页面，修复实际问题。复用会话已有授权继续邮件、翻译及部署验证，仅缺少必要登录或授权时询问实际缺项。

```text
python <skill-dir>/scripts/site_package.py check <project-dir>
python <skill-dir>/scripts/site_package.py pack <project-dir> --output <项目目录外>/<项目>-server.zip
```

每个交付目标分别检查、打包并提供直接下载；默认双包不嵌套成合集。包内含源码、锁文件、公共模块及中文配置与交接说明，排除依赖目录、运行数据、私人附件和凭据。交付文档及检测范围按 acceptance.md 记录。

请求部署时沿用已有授权，通过原工作台上传或原项目更新。既有项目沿用原持久存储；验证公网访问、核心页面、所改功能和工作台项目记录后才报告部署完成。

结构、业务运行、外部服务、内容素材和视觉分别报告。供应商接受邮件不等于送达或实收；译文 ready 不等于语言质量通过。未查看画面或未接通服务时明确未验证，不把离线检查汇总成完整验收。

## 交接与维护

继续项目先读实际工程及交接记录，修改内容来源或模板，避免仅改会被覆盖的生成页面。记录 skill/core/协议版本、参考库来源、数据边界及更新回滚方式。宿主缺少文件、执行或预览能力时说明具体缺口并继续可完成部分。

更新本 Skill 不自动升级旧网站或工作台。维护者按仓库规则验证并同步版本、更新记录和文件摘要，发布后保留 versions/v<版本号> 固定分支，不覆盖旧快照。公开仓库不含私人项目数据、凭据或本机绝对路径。
