# 交付一致性

仅针对实际交付目标打包，默认服务器；是否额外交付 Cloudflare 包遵从主入口及用户要求。工作流资料与网站部署包分别交付，不为每个网站强制新增证据合集。

先确定当前 Skill 和项目版本，刷新文件摘要与暂存目录，再检查、压缩、干净解压启动。核对 site.contract.json、workflow.json（如使用）、运行入口和 healthz 的发布值；不一致时先修复。使用 scripts/stage_app.py 增量镜像时目标只能是专用暂存目录，不得指向运行数据或已有客户工程；不得清空未知目录。旧包保留或归档，使用含版本的新文件名。

scripts/check_core_sync.py 检查共享核心漂移；scripts/lint_seed.py 检查初始中文块覆盖；scripts/delivery_manifest.py 生成交付ZIP摘要。它们不证明服务接通或视觉通过。

部署前确认项目ID、现有地址和原目录；继续项目走原更新流程，保留数据、账号、附件和域名。交付列项目名、版本、访问地址、工作台项目ID及绑定来源，避免不同目录误覆盖同一在线项目。公网检查与工作台记录均完成后才报告部署成功。
