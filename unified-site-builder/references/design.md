# 设计与内容

新建、改版或整理用户参考库时配合 [参考库与风格选择](style-selection.md)，根据产品和客户决定布局，并用项目记录减少连续建站的重复。
新建站先按 [通用基础框架](site-foundation.md) 明确页面和内容职责，再决定各页面或模块采用的参考。改造时仅应用于本次范围。基础能力有统一要求，展示布局可以按业务改变。

产品站围绕选型、规格、用途和询价；服务站围绕范围、流程和咨询。结构协议统一，品牌、布局、配色、图片和行业字段独立设计，不强制所有站同模板或三种主题。
商店模板同样纳入视觉候选，优先学习首页、品牌介绍、服务、文章、联系等非商店页面与整体外观，不因电商分类排除。默认交付企业展示与询盘站；行动入口按报价、定制咨询、索取目录与 WhatsApp 沟通设计。购物车、结账、支付和顾客订单仅在用户另外要求时实现。选择外观不改变后台与接口协议。
首页说明提供什么、面向谁、可核实优势及下一步。分类按买家任务组织；有关键词和参考时调查，不编造搜索量或以大量替换关键词的重复页面充数量。
设计变量集中定义，正式生成方式完成首页、列表/详情、询盘及手机样板后扩展。
参考确定后按 [图片制作与页面验证](visual-production.md) 规划、准备或生成实际素材，接入正式页面。内容丰富度按基础框架逐页核对；图片与版式共同表达产品细节和采购信息。
未知认证、产能、价格、交期、案例不编造。公开页隐藏未确认声明，后台和交付清单记录；专业事实按领域查可信来源，建站模板不作专业保证。
电脑与手机实际查看菜单、卡片、轮播、筛选、表单、长文和浮动联系入口；无障碍标签、键盘焦点、对比度与减少动画可用。
文章/产品响应含正文、标题、描述、H1与内部链接；404真实返回；canonical与sitemap来自站点配置。结构化数据不编造价格/评价，不承诺排名。程序通过不能代替视觉和内容验收。

## 设计规格与实现交接

新建或整体改版时使用 assets/design-spec.json 编制 docs/design-spec.json。docs/DESIGN.md 解释设计目的、模块顺序与来源；JSON 保存实际参数，代码变量落实取值。三者修改时同步核对，不能各有一套冲突数值。

规格按本产品填写，未确定项标记待补。覆盖字体层级、内容宽度、响应式布局、组件状态、图片裁切、动效用途及减少动态。页眉、首屏、页脚和详情模块按项目补充，不把字段齐全等同设计完成。区分原文要求、推导、改编和原创补充；不能把参考缺项编造成品牌规定。

项目主题只接收公开呈现数据和已解析译文，不传入数据库、账户、询盘、密钥或存储。ctx.blocks 是缓存/人工/初始译文快照；ctx.renderBlock(contentId, blockId) 输出含异步补译标记的安全文本。自定义主题必须保留语言切换、补译状态与重试入口，或明确实现同等协议。默认使用 ctx.document(ctx) 保留这些公共入口。主题错误应报错，不能吞掉内部依赖缺失或伪装404。

生成器提供返回 null 的项目主题占位入口，默认使用公共呈现。Worker 用静态导入以便打包器收集项目主题；升级旧工程时缺少该文件才补入占位文件，已有主题必须保留并适配，不能覆盖。Node 仍兼容完全没有主题文件的旧工程。
