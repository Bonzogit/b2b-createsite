# 跨平台交接

## 完整交接包与定位

公开仓库包含 README.md、AGENT_ENTRY.md、unified-site-builder/ 和 site-reference-library/。首次从 AGENT_ENTRY.md 进入。Skill 可以单独安装，用户参考库独立维护。包内 agents/openai.yaml 仅是支持该格式的平台元信息；其他平台从 SKILL.md 开始，不依赖它才能工作。

参考库读取顺序：
1. 本次用户明确指定的参考库或已配置的共享位置。
2. 完整交接包中，从 SKILL.md 所在文件夹定位 ../site-reference-library/design-library.json。
3. 当前项目交接文档记录的参考库位置或项目内快照。

资产 assets/design-library.json 是空白模板，不是附带的45条公开参考目录。找不到真实参考库时说明缺失，可按当前产品与新参考继续设计，但不能声称用过共享库。不要写死原作者电脑路径或向无权限位置搜索其他项目。

在项目 docs/HANDOFF.md 中记录 skillVersion、contractVersion、referenceLibrarySource、referenceLibraryRevision、runtime 和已有公共核心的实际版本。referenceLibrarySource 可使用解压后的相对路径、用户指定共享路径或附件标识，不记录密码。分发ZIP是版本快照，不会自动同步；新旧记录合并保留稳定ID与用户修改，不整库覆盖。

## 第一次接收

若用户只是安装/学习规范，说明实际读到的 Skill 版本、参考条目数量、能否读写工程、运行检查、准备/生成图片及查看实际页面，以及尚未读取的资源即可；不要创建示例网站或声称已永久记住。支持持久项目规则的平台，可在当前项目规则文件中加入简短入口，保留已有内容；平台是否支持原生Skill导入以实际能力为准。

执行建站任务时，沿用已确认的产品、品牌、目标客户与部署目标，避免重复询问。没有目标且无法从上下文判断时按主入口的Node默认。缺少的企业事实、资质和联系方式留作后台待配置，不编造。

使用实际文件修改能力建工程；做不到解压、代码执行或预览时，清楚标记相应范围未验证，不能把文字承诺当作已实现功能。不要求用户先认识部署工作台：按对应部署文档生成包，并解释仍需配置的外部服务。

## 更换 Agent 或升级规则

继续已有项目时先读实际工程及 docs/HANDOFF.md，保留文章、询盘、账户、媒体和用户设计。旧版项目按记录的版本运行；升级规范不自动迁移数据库或重置页面。接口差异使用兼容映射，需迁移时说明计划和实际结果。

交付说明分别回答：功能是否已实现、外部服务是否已接通、是否在目标工作台实际部署、内容与素材是否完成、哪些视觉与运行测试已完成。各项状态不能混用。离线检查脚本通过不等于网站运行成功；本包没有云账户凭据；1.6.0 附可运行基础后台参考，具体能力及真实验收边界见 runtime-profiles.md。
