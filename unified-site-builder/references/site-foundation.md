# 通用建站基础框架

这是各种产品和服务都可使用的起点。先落实网站目标、内容与业务行为，再选择展示形式。用户明确的业务要求优先，参考网站帮助决定外观和组织方式，不替代本框架中的询盘能力。

## 一、默认定位与访客任务

建立面向海外客户的B2B企业展示与询盘独立站，帮助访客理解供应内容、判断是否适合、核实供应商能力并提交需求。默认英文源内容，中文管理后台，语言及翻译执行 translation.md；市场按用户资料确定，未给时以海外采购沟通为假设，不虚构覆盖地区或客户。

默认视觉要求是清楚、专业、易读，适配电脑、平板和手机；具体风格、色彩、布局、摄影及模块组织按产品、客户和参考库选择。可以精品画册、技术说明、户外场景或目录导向，不把“专业”限定为同一套蓝白企业模板。

每个项目回答：卖什么或提供什么服务、面向谁、客户如何选型、凭什么信任、如何联系。产品名称足以启动规划；企业身份、地址、资质、产能、案例、回复时限等事实必须来自已确认资料。

## 二、基础页面与内容职责

下表说明应覆盖的信息，不规定每站相同的页面数量、模块顺序和视觉布局。内容少时可合并相近页面，并在项目记录说明对应位置；避免空壳页面。按业务替换产品/服务等名称。

| 页面或区域 | 基础内容与访客目的 | 适配方法 |
|---|---|---|
| 首页 | 供应内容与定位、产品/服务入口、采购理由、真实能力证据、合作方式、明显的咨询入口 | 首屏可用图片、视频、静态构图或适当轮播；优势数量与顺序按事实决定，不固定三列 |
| 产品/服务列表 | 分类、清楚的图片或示意、名称、核心规格或范围、详情与询盘入口 | 条目少时直接浏览；条目多时按有意义的字段搜索/筛选，不制作无作用的筛选器 |
| 产品/服务详情 | 图文说明、参数/材料或服务范围、用途、选型信息、相关内容及带上下文的询盘 | 按真实资料展示尺寸、型号、定制、起订量、交付条件等，不把工厂字段硬套给服务企业 |
| 关于我们 | 企业身份、定位、经历、团队或能力、合作方式 | 有真实历史才写年份和里程碑；结合品牌需要选择叙事方式 |
| 实力与质量 | 真实场景、流程、质控、已核实资质及相关案例 | 制造商可展示工厂；贸易商展示选品与供应链；服务商展示团队和服务流程。可独立成页或并入关于/详情 |
| 定制与合作 | 可提供的定制/合作范围、流程、客户应准备的资料与咨询入口 | 确有OEM/ODM才使用该名称；不适用的行业改为合作流程或省略，说明理由 |
| 文章与知识 | 文章列表、分类、独立正文、日期、相关内容和合适的咨询入口 | 支持后台持续发布；没有真实内容时采用明确空状态或隐藏导航，不捏造企业新闻 |
| 联系与询盘 | 真实联系信息、需求表单、适当附件、WhatsApp入口、保存成功与失败反馈 | 联系信息缺失时后台标记待配置；默认表单可收姓名、邮箱、公司、需求及可选附件，行业额外字段按采购任务确定 |
| 隐私与Cookie说明 | 如实说明本网站实际收集的信息、用途和所用服务，提供对应设置入口 | 按已实现的数据流和目标市场完善，不能仅靠通用弹窗宣称合规；不编造经营者或隐私联系信息 |

导航应让访客快速找到供应内容、公司能力和联系入口；页脚集中真实联系方式、必要导航和政策入口。主页和详情页提供清楚的下一步，不要求每个模块都重复放同一表单。

客户见证、客户Logo、认证、工厂实拍和“12小时回复”等仅在有依据时展示。缺少资料时可用实际可描述的采购流程、产品知识或待配置后台字段，公开页面不显示虚构证明或未经确认的占位承诺。

## 三、基础功能与配置边界

- 后台提供上述已采用内容的真实管理：页面模块、产品/服务、分类、文章、公开媒体、询盘、联系方式及设置。内容的增删改查与排序/发布按类型实现；不以能改几行文字就声称整个网站可管理，也不默认承诺任意拖拽编辑器。
- 管理操作、数据模型和业务接口统一，前台组件通过标准内容与接口呈现。具体遵循 business-contract.md、admin-ui.md、resend-email.md 和 translation.md。
- 询盘先保存，邮件单独处理；WhatsApp按配置号码打开沟通。后台编辑、新文章、语言切换和重启后数据保留必须按验收要求验证。
- 地图、额外在线聊天和统计代码作为可选配置入口，默认关闭。接入后验证来源、实际加载和相关隐私选择；无配置不展示空白嵌入或假聊天。Cookie设置根据实际使用的技术实现，不为一个装饰性弹窗自动添加跟踪服务。
- SEO基础包含各页面合理标题/描述、语义标题、真实正文HTML、清楚的链接和网站地图；关键词按具体行业确定，不沿用其他行业的例词，结构化数据只表达真实内容。
- 实际检查三类屏幕的导航、表单、参数表、长文、图片和浮动入口；阿拉伯语按RTL检查。技术规格详见设计和验收文档。
- 完整交付包含前台、服务端、持久化、中文后台和目标部署说明。可返回或生成HTML正文；仅静态HTML不能代表真实后台、邮件、询盘和AI已经完成。

## 四、先规划内容，再参考设计

建站时在 docs/SITE-BRIEF.md 简短记录：产品/服务与目标买家、确认事实和假设、页面及其目的、需要的内容与后台管理项、询盘路径、部署目标、待配置服务。记录后继续工作，不把一般设计选择变成必须等待用户批准的步骤；仅对无法继续的关键缺失提出问题。

然后按 style-selection.md 选择整站参考或模块组合。把每个采用模块的用途、参考来源和品牌适配写入 docs/design-record.json，再使用一致的字体、色彩、间距和组件实现。参考可以决定模块如何呈现，也可以帮助优化顺序与内容组织；不能因为某模板没有询盘或文章，就悄悄丢掉本项目需要的能力。

交付前核对页面内容、后台管理、接口与实际页面是否一一对应。合并、增加或省略某项按业务说明理由。保留后台与接口一致性，同时让前台设计服务于本产品及客户。
